# The social sharing card

Until now the site had no `og:image` at all: a link to revive.blog pasted into
Twitter, Slack or Discord unfurled as a bare title and one line of text. This
adds a 1200×630 PNG of the graveyard — the night sky, the moon, six lit
headstones — with the project name and the domain, generated on the server
from live funding data.

## What changed

- `lib/og.tsx` — the whole card: scene, data fetch, and `renderOgImage()`.
- `app/opengraph-image.tsx`, `app/twitter-image.tsx` — the two Next metadata
  file-convention routes. Both are three lines that call `renderOgImage()`.
- `app/layout.tsx` — `metadataBase`, plus `openGraph` and `twitter` blocks.
- `assets/fonts/CrimsonPro-Medium.ttf`, `assets/fonts/MarcellusSC-Regular.ttf`
  — the two faces the card draws with, committed as TTF.
- `next.config.ts` — `outputFileTracingIncludes` for those two fonts.
- `lib/graveyard.ts` — new home for scenery shared between the graveyard skin
  and the card: `eyebrowFor`, `starField`, `TREE_PATH`, `GRASS_PATH`. Moved out
  of `components/graveyard/Headstone.tsx` and `GraveyardHero.tsx`.
- `lib/qf.ts` — `DEFAULT_POOL_CENTS` / `DEFAULT_LIVE_THRESHOLD_CENTS` moved
  here from `lib/hooks.ts`, which now imports them.
- `scripts/og-preview.ts` — renders the card to a PNG on disk.

## How it works

`/opengraph-image` reads the bloggers and settings through the admin SDK, runs
the same `computeQf` the homepage runs, sorts live-then-total, and hands the
top six to the scene. Stone size, candle wax height and glow strength all scale
with funding, so the card gets brighter as bounties fill — a live bounty's
candle is lit, an unfunded one shows bare wax.

The route is static with `revalidate = 3600`: it renders once at build and
refreshes hourly. Crawlers hit these URLs hard and each render is a database
round trip, so an hour of staleness is the right trade. A failed query yields
an empty plot rather than a failed image — `topStones` is wrapped in a `catch`
because crawlers don't retry.

`app/twitter-image.tsx` renders the identical card. X falls back to `og:image`
on its own, but only once `twitter:card` is declared; declaring both leaves
nothing to infer.

## Gotchas

**Satori is not a browser.** `next/og` lays out a subset of CSS and knows
nothing about Tailwind, `globals.css`, or `@font-face`, so the scene is rebuilt
in `lib/og.tsx` with inline styles rather than reusing `GraveyardHero`. The
constraints that actually bit:

- Any element with more than one child needs an explicit `display`. This
  includes text: `silent {n} days` is _three_ children and throws. It has to be
  a single interpolated string.
- Through the route that error surfaces only as `Error: failed to pipe
response` with no stack, and the response is still a valid-looking PNG with
  the broken subtree silently missing. `bun run scripts/og-preview.ts` throws
  the real message instead — use it when the card renders wrong.
- `z-index` is unsupported and warns; paint order is DOM order.
- No `background` shorthand for gradients (use `backgroundImage`), no
  elliptical `/` border-radius syntax, no animations.
- `inset` box-shadows are dropped. The hero's stones get their weight from
  `inset 0 -26px 40px`; without it they render milky and barely separate from
  the sky, so the stone gradient carries a third dark stop instead.

**Fonts are read off disk.** `next/font/google` can't hand out the buffers
Satori needs, so the TTFs are committed and read with `fs`. The bundler can't
see a runtime `readFile`, hence the `outputFileTracingIncludes` entry — without
it the fonts are missing in production and every glyph falls back. Verify with
`.next/server/app/opengraph-image/route.js.nft.json` after a build.

**Trees have to be rooted above the ground band.** They're filled the same
near-black as the foreground hills, so a tree planted at the bottom of the
frame loses its trunk and reads as branches floating in mid-air.

**Dev serves stale metadata.** Editing `metadata` in `app/layout.tsx` doesn't
reliably reach a running dev server — `og:url`, `og:site_name` and `og:type`
kept coming back missing while the file-convention tags updated fine. Check the
prerendered `.next/server/app/index.html` after a build, not the dev server.
Note also that `og:image` is absolute against the dev host in development and
against `metadataBase` in production.
