# Mobile layout pass

Both skins were desktop designs with breakpoints bolted on: the graveyard hero
degraded to a two-column grid of squat mini-stones, the blogroll headstones
stretched into wide flat arches, and the WordPress Meta widget stacked nine
links and a heading above the first line of the post. This pass gives each
skin a deliberate phone layout instead of a narrowed desktop one.

The governing idea: the top of a phone screen is the only real estate a
visitor is guaranteed to see, so nothing decorative or navigational gets to
spend it.

## What changed

- **`components/graveyard/Nav.tsx`** — the header renders nothing below `md`
  on the home route, so the hero's own "Blog Revival Project" is the first
  line on the page. Other routes keep a bare wordmark as the way home. The
  nav links and the gold "become a patron" button are `sm:`-only; the mobile
  fallback for the CTA is a plain "sign in" link. Everything the mobile header
  dropped now lives in the footer nav, including account/sign-in, which the
  footer never carried before.
- **`components/graveyard/GraveyardHero.tsx`** — the mobile grid of six
  mini-stones is replaced by three overlapping stones standing on the ground
  line, `mt-auto` inside a `min-h-[100svh]` flex column. The copy runs one
  primary button with "how it works" demoted to a text link, and one tree
  joins the scene at the left edge.
- **`components/graveyard/Headstone.tsx`** — a `sm:hidden` plaque row
  (cameo, engraved name, amount, silent days + patron count, progress) sits
  alongside the existing arch card, which is now `hidden sm:flex`.
- **`components/graveyard/pages/home.tsx`** — the blogroll container is a
  divided list on phones and the stone grid from `sm` up; section padding and
  heading sizes step down on mobile.
- **`components/graveyard/pages/blogger.tsx`** — the three blocks are now
  explicitly grid-placed so the phone order is state → pledge box → reading
  matter, instead of burying the pledge box under the register.
- **`components/wordpress/Meta.tsx`** — one `useMetaLinks()` list feeds two
  shapes: the sidebar widget (`md`+) and `WpMetaBar`, a wrapped strip of
  dot-separated links with shorter labels.
- **`components/wordpress/Shell.tsx`** — the Meta column is dropped below
  `md` (not stacked) and the bar renders as the first row inside the white
  panel; header, panel and main padding step down on mobile.
- **`app/globals.css`** — fields go to 16px under 640px in both skins.
- **`components/graveyard/Shell.tsx`** — `overflow-x-clip` on the skin wrapper.
- **`components/ThemeFab.tsx`** — one shared position string for both skins,
  lifted clear of the iOS home indicator.

## How the mobile plot works

`MOBILE_SLOTS` is ordered `[second, first, third]`, so the best-funded bounty
stands center, tallest and in front, with the flanking pair set back — higher
baseline, darker gradient, lower z-index. The overlap (percentage widths
summing to 102%, then `-8px` margins) is what buys the size: three stones
packed flat across a 375px screen are ~110px each and the engraved names go
illegible, whereas letting them crowd each other lets the front stone run
wider than a third of the screen.

Because the stones are sized as a share of the viewport, their engraving can't
be sized in px. Each stone sets `container-type: inline-size` and `nameCqw()`
returns a font size in `cqw` — percent of the stone's own width — using the
same ~0.8em-per-glyph estimate as the desktop `nameSize()`. The eyebrow and
the days-silent line are dropped at this size; both engrave down to noise, and
both are repeated on the plaque rows further down the page.

Names never break across lines, the way they don't on the desktop stones: a
long one engraves small instead. Breaking was tried and reverted — a
hyphenated name on a headstone reads as a mistake, and letting the browser
choose the point is worse still, since `hyphens: auto` takes the _last_
dictionary break that fits ("aschenbren-ner").

## Gotchas

- The hero section is `flex flex-col` only below `md` (`md:block`), and the
  stone row's `mt-auto` is what pins the plot to the ground. The hills are
  absolutely positioned against the section's bottom edge, so as long as the
  row's `pb` keeps the bases within roughly 40–140px of that edge they read as
  standing on the ground — the same band the desktop `SLOTS` occupy.
- `Headstone` now returns a fragment of two siblings, so the blogroll
  container gets two children per blogger, one of them `display:none` at any
  width. That rules out `divide-y` (it would count the hidden ones): each
  mobile row carries its own `border-t` and the container the closing
  `border-b`.
- The graveyard scene is full of elements that run past their own boxes — a
  candle glow is up to 213px wide around a 12px wick, and a grave mound sits
  10% proud of its stone on each side. Inset from the edges on a desktop
  they're invisible; on a phone the plot reaches close enough to the viewport
  edge that they gave the page a horizontal scrollbar. Hence `overflow-x-clip`
  on the `.gy` wrapper — `clip` rather than `hidden` so it doesn't become a
  scroll container.
- `env(safe-area-inset-bottom)` needs its `0px` fallback spelled out. Without
  one the declaration is invalid wherever the variable is unset, so `bottom`
  falls back to `auto` and a `position: fixed` button drops out of its corner
  to wherever it landed in flow.
- The 16px field rule in globals.css is unlayered, so it outranks any
  Tailwind `text-*` utility on the same element regardless of specificity —
  which is the point, since iOS zooms the viewport on any field under 16px and
  never zooms back out. The WordPress skin is a 13px design throughout, so
  every field in it was affected.
- `bun run format` reformats `docs/*.md` and mangles wrapped list items. Check
  `git status` after running it and revert docs it touched.
